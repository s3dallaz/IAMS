HOW THE ALGORITHM WORKS
================================================================================

Phase 3B Liveness Detection Algorithm Overview:
-----------------------------------------------

The algorithm detects liveness through passive blink detection using a
multi-step temporal analysis process:

Step 1: Facial Landmark Extraction
-----------------------------------
- Uses MediaPipe Face Landmarker to extract 478 facial landmarks
- Focuses on eye region landmarks:
  * Left eye: indices [33, 160, 158, 133, 153, 144]
  * Right eye: indices [362, 385, 387, 263, 373, 380]
- Converts normalized coordinates (0-1) to pixel coordinates
- Handles missing landmarks gracefully (returns None if detection fails)

Step 2: Eye Aspect Ratio (EAR) Calculation
-------------------------------------------
For each eye, EAR is calculated using the formula:

    EAR = (||p2-p6|| + ||p3-p5||) / (2 * ||p1-p4||)

Where:
- p1, p4 are horizontal eye corners (horizontal distance)
- p2, p3, p5, p6 are vertical eye points (vertical distances)

EAR Interpretation:
- Open eye: EAR ≈ 0.3-0.4
- Closed eye: EAR < 0.23 (threshold)
- Average of both eyes used for robustness

Step 3: Blink Detection State Machine
--------------------------------------
Tracks eye state through a 4-state machine:

1. OPEN (initial state)
   - Eyes are open (EAR ≥ threshold)
   - Transitions to CLOSING when EAR drops below threshold

2. CLOSING (transitional)
   - EAR below threshold but not yet confirmed
   - Requires consecutive frames below threshold to confirm
   - Prevents false positives from single-frame noise
   - Transitions to CLOSED after 2 consecutive frames
   - Reverts to OPEN if eyes reopen before confirmation

3. CLOSED (confirmed closure)
   - Eyes confirmed closed for consecutive frames
   - Transitions to REOPENING when EAR rises above threshold

4. REOPENING (transitional)
   - EAR above threshold after closure
   - Requires consecutive frames above threshold to confirm
   - Complete blink detected when confirmed
   - Reverts to CLOSED if eyes close again before confirmation

Complete Blink Cycle:
OPEN → CLOSING → CLOSED → REOPENING → OPEN
                  ↓
            Blink Counter++

Step 4: Temporal Analysis Across Sequence
------------------------------------------
Process each frame in sequence:
1. Extract eye landmarks
2. Calculate EAR for both eyes (use average)
3. Update blink detection state machine
4. Track blink count across sequence
5. Monitor frames with valid landmarks

Step 5: Liveness Classification
--------------------------------
After processing all frames, classify based on:

- Frame Count Check:
  * If frames < min_frames (default: 10) → UNKNOWN

- Landmark Availability Check:
  * If valid landmarks < 50% of frames → UNKNOWN

- Blink Detection Check:
  * If blinks ≥ min_blinks (default: 1) → LIVE
  * If blinks < min_blinks → UNKNOWN (not SPOOF)

Confidence Calculation (for LIVE):
- Base confidence: liveness_threshold (0.75)
- Additional confidence: +0.05 per blink above minimum
- Capped at 1.0

================================================================================
LIVENESS STATE CLASSIFICATION CRITERIA
================================================================================

LIVE State Criteria:
-------------------
A face is classified as LIVE when ALL of the following are true:
1. frame_count ≥ min_frames (default: 10)
2. valid_landmark_frames ≥ 50% of total frames
3. blink_count ≥ min_blinks (default: 1)

Example LIVE Result:
    LivenessResult(
        state=LIVE,
        confidence=0.75-1.0,
        frame_count=15,
        reason="Blinks detected: 1 (threshold: 1)"
    )

UNKNOWN State Criteria:
----------------------
A face is classified as UNKNOWN when ANY of the following are true:
1. frame_count < min_frames
2. valid_landmark_frames < 50% of total frames
3. blink_count < min_blinks
4. Single-frame detection (insufficient for temporal analysis)
5. Landmark extraction failed

Example UNKNOWN Results:
    - "Insufficient frames: 5 < 10 required"
    - "Insufficient valid landmarks: 3/15 frames"
    - "Insufficient blinks: 0 < 1 required"
    - "Single frame insufficient - use detect_liveness_sequence()"

SPOOF State:
-----------
Phase 3B does NOT classify faces as SPOOF. Rationale:
- Lack of blinks alone is not sufficient evidence of spoofing
- Person may be concentrating, reading, or naturally still
- Passive blink detection cannot distinguish between:
  * A still person
  * A high-quality photo
  * A paused video
- Returning UNKNOWN is more honest than false SPOOF classification
- Phase 3C will add additional anti-spoofing measures

KNOWN LIMITATIONS
================================================================================

Critical Limitation: Video Replay Attacks
-----------------------------------------
⚠️ Phase 3B blink detection alone CANNOT reliably prevent sophisticated
video replay attacks.

Specifically, the algorithm CANNOT distinguish between:
1. A live person blinking naturally
2. A pre-recorded video of that person blinking
3. A looped video segment containing blinks
4. A deepfake video with realistic blinks

Why This Occurs:
- Passive blink detection only analyzes facial landmarks and movements
- A high-quality video replay will show identical landmarks and movements
- The algorithm has no mechanism to detect:
  * Video artifacts or compression
  * Screen reflections or display boundaries
  * Lack of depth information
  * Temporal replay patterns

Attacks This DOES Prevent:
- Static printed photos (no blinks)
- Low-quality photos held up to camera (no blinks)
- Frozen video frames (no blinks)
- People trying to avoid blinking for extended periods

Attacks This DOES NOT Prevent:
- High-quality video replay with blinks
- Looped video segments
- Deepfake videos
- Videos played on high-resolution screens
- Pre-recorded blink sequences

Recommended for:
- Initial screening in low-security scenarios
- Detection of casual spoofing attempts
- Educational/demonstration purposes
- Combination with Phase 3C anti-spoofing measures

NOT Recommended for:
- High-security authentication alone
- Financial transactions
- Access control to sensitive areas
- Any scenario where video replay is a realistic threat

Other Limitations:
------------------
1. Lighting Dependency
   - Poor lighting may prevent landmark detection
   - Very bright lighting may affect EAR calculation
   - Shadows can interfere with eye detection

2. Face Orientation
   - Works best with frontal face orientation
   - Profile views may not detect eye landmarks
   - Extreme angles reduce accuracy

3. Occlusions
   - Glasses with strong reflections may interfere
   - Sunglasses prevent eye landmark detection
   - Partial face occlusions affect reliability

4. Natural Variation
   - Some people blink less frequently
   - Concentration or focus reduces blink rate
   - Medical conditions may affect blinking
   - May require longer sequences for some users

5. Performance
   - MediaPipe landmark detection adds computational overhead
   - Processing 10-30 frames takes 1-3 seconds on typical hardware
   - Real-time processing requires optimization

6. False Positives Possible With:
   - Rapid eye movements mistaken for blinks
   - Head movements causing landmark detection fluctuations
   - Camera motion or instability

================================================================================
ALGORITHM PARAMETERS TUNING NOTES
================================================================================

EAR_THRESHOLD = 0.23
------------------
Literature reference: Soukupová & Čech (2016) "Real-Time Eye Blink Detection"
Typical range: 0.20-0.25

Tuning considerations:
- Lower threshold (0.20): More sensitive, may detect partial closures
- Higher threshold (0.25): More strict, requires fuller closure
- Current value (0.23): Balanced for general use

EAR_CONSECUTIVE_FRAMES = 2
--------------------------
Rationale: Human blinks typically last 100-400ms
At 30 FPS: 3-12 frames per blink
At 15 FPS: 1.5-6 frames per blink

Current setting (2 frames):
- Confirms closure without being too restrictive
- Works at both 15 FPS and 30 FPS
- Prevents single-frame noise

Alternative values:
- 1 frame: More sensitive but prone to false positives
- 3+ frames: More robust but may miss quick blinks

MIN_BLINKS = 1
--------------
Current setting: Requires at least one blink for LIVE classification

Alternative values:
- 0 blinks: For testing or very permissive scenarios (not recommended)
- 2+ blinks: Higher security but longer wait time for users

Typical blink rates:
- Normal: 15-20 blinks per minute
- Concentrated: 5-10 blinks per minute
- Over 2 seconds (default window): Expect 0-1 blinks

MIN_FRAMES = 10
---------------
At 15 FPS: 0.67 seconds
At 30 FPS: 0.33 seconds

Current setting ensures sufficient temporal data for at least one blink.
