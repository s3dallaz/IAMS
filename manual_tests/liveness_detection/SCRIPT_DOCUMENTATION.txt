================================================================================
DISPLAYED INFORMATION
================================================================================

The live video overlay shows:

1. State (color-coded)
   - LIVE (Green): Blinks detected, liveness confirmed
   - UNKNOWN (Orange): Insufficient evidence or no blinks
   - SPOOF (Red): Not used in Phase 3B

2. Confidence
   - Range: 0.0 to 1.0
   - Increases with more blinks detected
   - Base: 0.75 for LIVE with 1 blink

3. Blinks Detected
   - Count of complete blink cycles detected
   - Extracted from LivenessResult reason field

4. Buffered Frames
   - Current buffer size / Maximum (30)
   - Shows X/30 format

5. Detections Run
   - Number of times liveness detection executed
   - Runs every 10 frames

6. Face Bounding Box
   - Green rectangle around detected face
   - Only shown when face is detected

================================================================================
HOW IT WORKS
================================================================================

Architecture:
------------

1. CameraManager captures frames from webcam
2. FaceDetector detects face and returns bounding box
3. Frames with faces are added to rolling buffer (max 30 frames)
4. Every 10 frames, LivenessDetector analyzes the buffered sequence
5. Results displayed as overlay on live video feed

Rolling Buffer:
--------------
- Maintains last 30 frames with detected faces
- Older frames automatically removed
- Only frames with valid face detections are kept
- Resets when sequence is manually reset (R key)

Detection Interval:
------------------
- Liveness detection runs every 10 frames
- Reduces computational overhead
- Provides periodic updates (~0.3-0.7 seconds)
- Results displayed continuously until next detection

LivenessTestSession Class:
-------------------------
- Manages frame and face buffers (deques with maxlen)
- Tracks statistics (total frames, detections, etc.)
- Interfaces with LivenessDetector
- Extracts blink count from result reason string
- Provides reset functionality

Overlay Drawing:
---------------
- Semi-transparent dark overlay at top of frame
- Color-coded state indication
- Real-time statistics display
- Face bounding box when detected
- Control hints at bottom

================================================================================
TESTING SCENARIOS
================================================================================

Scenario 1: Live Person Blinking
---------------------------------
Procedure:
1. Position face in frame
2. Blink naturally 1-2 times
3. Wait for detection to run

Expected:
- State changes to LIVE (green)
- Blinks Detected: ≥ 1
- Confidence: 0.75+

Scenario 2: No Blinking
-----------------------
Procedure:
1. Keep eyes open for 5+ seconds
2. Observe state remains UNKNOWN

Expected:
- State: UNKNOWN (orange)
- Blinks Detected: 0
- Reason: "Insufficient blinks"

Scenario 3: Face Loss/Recovery
------------------------------
Procedure:
1. Start with face in frame
2. Move out of frame
3. Return to frame

Expected:
- Buffer empties when face lost
- Buffer rebuilds when face returns
- Fresh detection starts

Scenario 4: Reset Function
--------------------------
Procedure:
1. Accumulate frames and blinks
2. Press 'R' key

Expected:
- Buffer clears to 0
- State resets to UNKNOWN
- Blinks reset to 0
- Console message: "[INFO] Sequence reset"

COMPONENT REUSE
================================================================================

The script reuses existing production components:

1. CameraManager (from Phase 2B)
   - camera.open()
   - camera.read_frame()
   - camera.release()
   - camera.get_frame_dimensions()

2. FaceDetector (from Phase 2C)
   - detector.detect_faces(frame)
   - detector.close()
   - Returns list of DetectedFace objects

3. LivenessDetector (from Phase 3B)
   - detector.detect_liveness_sequence(frames, faces)
   - Returns LivenessResult object
   - No modifications to production code

4. Data Classes
   - DetectedFace: bbox and confidence attributes
   - LivenessResult: state, confidence, frame_count, reason attributes
   - LivenessState: LIVE, SPOOF, UNKNOWN enum values

No production code was modified. All components used via public APIs.

================================================================================
ERROR HANDLING
================================================================================

The script handles:

1. Camera Initialization Failure
   - Clear error message
   - Suggests checking webcam connection
   - Graceful exit

2. Missing MediaPipe Model
   - Catches FileNotFoundError
   - Shows download URL
   - Instructions for placement

3. Frame Read Failures
   - Warning message
   - Continues to next frame
   - Does not crash

4. Face Detection Failures
   - Handles empty detection list
   - No face added to buffer
   - Continues processing

5. Landmark Extraction Failures
   - Handled internally by LivenessDetector
   - Returns UNKNOWN state
   - Continues processing

6. Keyboard Interrupt (Ctrl+C)
   - Graceful shutdown
   - Shows summary
   - Releases resources

7. General Exceptions
   - Catches and displays error
   - Shows stack trace
   - Releases resources in finally block

All resource cleanup occurs in finally block:
- Camera released
- Detector closed
- OpenCV windows destroyed

PERFORMANCE CHARACTERISTICS
================================================================================

Typical Performance (on modern hardware):
- Frame Capture: ~15-30 FPS (depends on webcam)
- Face Detection: ~20-30ms per frame
- Landmark Extraction: ~30-50ms per frame
- EAR Calculation: <1ms per frame
- Total Processing: ~50-100ms per frame
- Detection Latency: 0.3-0.7 seconds (every 10 frames)

Memory Usage:
- Frame Buffer: ~10-20 MB (30 frames at 640x480)
- MediaPipe Models: ~20 MB loaded
- Total: ~50-100 MB

Frame Rate Impact:
- Without processing: 30 FPS
- With liveness detection: 15-25 FPS
- Acceptable for manual testing

LIMITATIONS AND WARNINGS
================================================================================

This script is for TESTING and DEMONSTRATION only.

What This Tests:
✓ Blink detection accuracy
✓ Temporal analysis behavior
✓ Face detection integration
✓ Real-time processing capability
✓ User experience and responsiveness

What This Does NOT Test:
✗ Video replay attack resistance
✗ Photo spoofing detection
✗ Production security readiness
✗ Edge cases requiring sophisticated spoofing
✗ Long-term reliability under all conditions

Known Issues:
1. Cannot detect video replays with blinks
2. May be sensitive to lighting changes
3. Requires frontal face orientation
4. Sunglasses prevent detection
5. Performance varies by hardware

This script demonstrates Phase 3B blink detection capabilities but does not
validate production security. Video replay attacks will succeed. Additional
anti-spoofing measures (Phase 3C) are required for real security.

================================================================================
TROUBLESHOOTING QUICK REFERENCE
================================================================================

Issue: Camera won't open
Solution: Close other apps using webcam, check connection, try camera_index=1

Issue: Model not found
Solution: Download face_landmarker.task to project root (see error message URL)

Issue: No face detected
Solution: Better lighting, face camera directly, move closer, remove sunglasses

Issue: State stays UNKNOWN
Solution: Blink more deliberately, wait for buffer to fill (10+ frames)

Issue: Low FPS / lag
Solution: Expected behavior, close other apps, landmark detection is intensive

Issue: Blinks not detected
Solution: Full eye closure required, check lighting, blink more slowly
